## 1. Timestral이 뭔가

**Timestral은 Mistral이 2026년 10월 15일에 공개한 첫 시계열 파운데이션 모델(TSFM) 계열**이다. 한 줄로 말하면 "학습해 본 적 없는 시계열도 바로 예측하는 사전학습 모델"이다.

| 항목 | 내용 |
|---|---|
| 종류 | 시계열 파운데이션 모델 (zero-shot 예측) |
| 크기 | 5M, 28M, 123M, 209M 파라미터 (네 가지) |
| 문맥 길이 | 최대 32,768 time step |
| 출력 | 확률적 예측, **21개 분위수(quantile)** |
| 입력 | 다변량(multivariate) 타깃, 과거 전용 공변량, 미래 기지 공변량, 범주형 공변량 |
| 하드웨어 | **GPU 없이 CPU에서 추론 가능** |
| 라이선스 | 코드는 Apache 2.0, 가중치는 Modified MIT (별도) |
| 배포 | 가중치는 Hugging Face, 추론 코드는 GitHub, 미세조정은 Mistral Forge |

## 2. 먼저 알아야 할 배경: 시계열 파운데이션 모델

발표 글은 시계열 예측 방식을 세 단계로 설명한다.

1. **고전 모델 (ARIMA, 선형 회귀 등)**: 보통 **시계열 하나**에 맞춰 학습하고 그 시계열의 과거에서만 배운다.
2. **딥러닝 모델 (PatchTST 등)**: 서로 관련된 많은 시계열에서 비선형 패턴을 배울 수 있지만, 보통 **데이터셋마다 처음부터** 학습한다. 배운 것이 다른 도메인으로 이어지지 않는다.
3. **시계열 파운데이션 모델**: 크고 다양한 데이터로 **사전학습**해서, 본 적 없는 데이터도 **zero-shot**으로 예측한다. 데이터가 적은 도메인에서도 쓸 수 있다는 것이 장점이다.

LLM이 텍스트에서 한 일을 시계열에 적용한 것으로 이해하면 된다.

## 3. 핵심 용어

- **Zero-shot 예측**: 대상 데이터로 학습하지 않고 사전학습된 모델에 과거 값을 넣어 바로 미래를 예측한다.
- **확률적 예측(probabilistic forecast)**: 한 개의 값이 아니라 **분포**를 낸다. Timestral은 21개 분위수(0.01, 0.05, 0.1, …, 0.9, 0.95, 0.99)를 낸다. 예측의 불확실성 폭을 볼 수 있고, 경보 기준을 그 폭에 맞출 수 있다.
- **다변량(multivariate)**: 관련된 여러 변수(예: 펌프의 진동, 온도, 압력)를 **함께** 모델링한다. 각 센서를 따로 예측하지 않고 변수 간 의존성을 쓴다.
- **공변량(covariate)**: 예측 대상은 아니지만 예측에 도움이 되는 입력이다.
  - *과거 전용*: 지난 구간에서만 아는 값
  - *미래 기지(known-future)*: 미래에도 미리 아는 값 (생산 일정, 계획된 가동 중지, 날씨 예보, 공휴일)
  - *범주형*: 요일, 설비 상태(가동/대기/정비)처럼 순서가 없는 값. 숫자로 억지 인코딩하면 없는 순서가 생기므로 범주형 입력으로 직접 받는다.

## 4. 구조와 학습: 핵심 기술 네 가지

발표 글이 꼽은 핵심은 다음과 같다. 자세한 내용은 기술 보고서에 나올 예정이라, 여기서는 공개된 설명 범위만 정리한다.

1. **Decoupled Horizon Forecasting (DHF)**
   - 기존 인과(causal) 디코더 방식(Toto 2.0, TimesFM-3 등)은 예측할 구간을 마스킹해서 결측값처럼 보이게 하고, 그 값이 이후 예측의 문맥에서도 사라진다.
   - DHF는 이 둘을 분리한다. **전체 과거를 시퀀스에 그대로 두고**, 학습된 **예측 토큰(forecast token)** 이 앞의 과거를 읽어서 예측한다. 그래서 관측된 값이 목표와 문맥 역할을 모두 하고, 진짜 결측은 결측으로 남는다. 학습 시 예측 길이와 결측 증강을 독립적으로 조절할 수 있다.
2. **공변량 인식 어텐션(covariate-aware attention)**
   - 입력 시리즈마다 역할을 준다: 타깃, 과거 전용 공변량, 미래 기지 공변량.
   - 미래 기지 공변량은 예측 구간 전체를 볼 수 있고 타깃은 인과적으로 유지된다. 정보는 **공변량에서 타깃 방향으로만** 흐른다. 그래서 휴일 달력이나 날씨 예보를 쓰면서도 타깃의 미래가 새어 들어가지 않는다.
3. **합성 데이터 우선(synthetic-first)**
   - 학습 데이터 대부분이 **합성 데이터**다. 먼저 추세, 계절성, 다양한 노이즈를 가진 단변량 과정을 만들고, 다변량 합성기로 이 과정들 사이에 비선형 의존성을 넣어 다변량 시계열을 만들었다.
4. **2단계 학습**
   - 1단계: 순수 합성 데이터로 문맥 길이 8,192에서 대규모 사전학습
   - 2단계: 실제 + 합성 데이터 혼합으로 **4배 긴 문맥**에서 후학습
   - 목적 함수: 21개 분위수에 대한 **핀볼 손실(pinball loss)**. CRPS를 이산적으로 근사한 것이다.

저장소 설명으로는, 모델은 **인과적 패치 기반 트랜스포머**이고, 분위수 헤드가 시간 스텝마다 서로 **교차하지 않는** 21개 분위수를 출력한다.

## 5. 성능과 효율 (모두 Mistral 발표 기준)

- 가장 큰 209M 모델이 공개 벤치마크 **GIFT-Eval, TIME, fev-bench**에서 사전학습 zero-shot 모델 중 1위라고 한다. 단일 체크포인트이고 앙상블은 쓰지 않았다.
- 크기별로 정확도 대 모델 크기의 **파레토 전선**에 있다고 주장한다. 28M 모델이 약 4배 큰 Chronos-2를 GIFT-Eval과 TIME에서 앞선다고 한다.
- **CPU 추론 속도**: 서버 CPU 8 스레드에서 "15분 간격 3주치 이력으로 하루 앞 예측"이 5M 모델 17ms, 209M 모델 113ms다. 28M 모델은 209M보다 3.6배 빠르고, 123M 모델은 209M 점수의 0.2% 이내를 4분의 3 지연시간으로 낸다.
- 모델 가중치 크기(fp32): 5M 21MB, 28M 111MB, 123M 490MB, 209M 837MB.

> 순위 그래프의 축이 0에서 시작하지 않는다(발표 글도 "막대 길이는 점수에 비례하지 않는다"고 밝힌다). 1위와 2위의 점수 차이는 작다. 순위만 보고 큰 우위로 읽지 않도록 주의한다.

## 6. 써보기 (저장소 README 기준)

설치. Python 3.10 이상, torch 2.4 이상이 필요하다.

```bash
pip install git+https://github.com/mistralai/timestral.git
```

예측.

```python
import numpy as np
from timestral import TimestralForecaster

forecaster = TimestralForecaster.from_pretrained("mistralai/Timestral-209M")  # GPU는 device="cuda"

context = np.random.randn(2, 1, 2000).cumsum(-1)  # (series, variates, time), NaN = 결측
forecast = forecaster.forecast(context, prediction_length=96)

forecast.quantiles.shape   # (2, 1, 96, 21)  series, variates, horizon, quantile
forecast.median            # (2, 1, 96)
forecast.quantile(0.9)     # (2, 1, 96)
```

- 입력은 `(B, V, T)`, `(B, T)`, `(T,)` 형태를 받는다. NaN은 결측이다.
- 문맥은 학습 길이(32,768)로 잘리고 **가장 최근 구간**이 유지된다.
- 한 디코드 블록(1,024 step)보다 긴 예측은 블록 단위로 이어서 하며, 각 블록의 **중앙값을 다시 문맥으로** 넣는다. 긴 horizon일수록 오차가 누적될 수 있다는 뜻이라 확인이 필요하다.

공변량.

```python
forecast = forecaster.forecast(
    context,
    prediction_length=96,
    past_covariates=past,     # (B, C_past, T)       문맥 구간만 아는 값
    known_covariates=known,   # (B, C_known, T+96)   문맥과 예측 구간 모두 아는 값
)
```

범주형 공변량은 숫자 코드(예: `pandas.factorize`)로 넣는다. 단변량 타깃이면 범주가 시리즈별로 target encoding되고, 다변량 타깃이면 원래 코드가 그대로 들어간다.

## 7. 어디에 쓸 수 있나

발표 글이 드는 예시는 산업 설비 센서 데이터다.

- 다변량 예측으로 센서 간 연관을 활용
- 분위수로 불확실성에 맞춘 경보 기준과 정비 계획
- 생산 일정, 계획된 가동 중지 같은 미래 기지 공변량으로 "예정된 부하 증가"를 이상으로 오인하지 않기
- 이상 징후를 감지한 뒤 LLM 에이전트가 과거 유사 고장 사례와 정비 기록을 찾아 진단을 작성하는 **멀티모달 에이전트 워크플로**와 결합

그 밖에 에너지, 공급망, 금융(흐름, 거래량, 변동성)의 수요/용량 계획 예측이 언급된다.

## 8. 한계와 확인할 점

- **자체 발표 수치**: 벤치마크 결과는 Mistral이 제출한 값이다. 기술 보고서가 나오면 평가 설정을 다시 확인해야 한다.
- **합성 데이터 비중**: 학습 데이터 대부분이 합성이라서, 내 도메인의 특이한 패턴에 얼마나 잘 맞는지는 직접 검증이 필요하다.
- **라이선스**: 코드는 Apache 2.0이지만 **가중치는 Modified MIT**다. 상업적으로 쓰기 전에 가중치 라이선스 본문을 직접 읽어야 한다. 이 글은 라이선스 본문을 검토하지 않았다.
- **미세조정은 Mistral Forge**: 문서 기준으로 도메인 특화 미세조정은 Mistral Forge를 통해 제공된다. 오픈소스 저장소만으로 학습 코드까지 있는지는 확인하지 못했다. 저장소는 추론 중심이라고 설명한다.
- **문서 상태**: Mistral 문서에는 모델이 **Public Preview**로 표시되어 있다.
- **긴 예측 구간**: 블록마다 중앙값을 피드백하는 방식이라 horizon이 길 때 정확도 변화를 직접 봐야 한다.
- **기존 모델과의 비교**: 같은 데이터에서 LSTM, PatchTST 같은 학습형 모델과 비교해 봐야 실질적인 이득을 안다.

## 9. 내 정리와 남은 의문

- 시계열 파운데이션 모델의 장점은 **학습 없이 바로 예측**한다는 것이고, 대가는 **내 데이터 분포에 맞춰 최적화되지 않는다**는 것이다.
- 확률적 예측이 기본 출력이라는 점이 실무에서 중요하다. 점 예측 하나보다 분위수가 의사결정에 더 쓸모 있다.
- 의문: 센서 데이터가 짧거나 특이할 때 zero-shot이 단순 베이스라인(마지막 값 유지, 계절 나이브)을 얼마나 이기나?
- 의문: 범주형 공변량을 target encoding으로 바꾸는 방식이 설비 상태 같은 변수에서 충분한가?

### 직접 해보고 채울 것

- [ ] 단순 베이스라인, 학습형 모델과 같은 지표로 비교
- [ ] 분위수 구간의 보정(실제 값이 80% 구간에 약 80% 들어오는지) 확인
- [ ] 미래 기지 공변량을 넣었을 때와 뺐을 때 차이
- [ ] 긴 horizon(1,024 step 초과)에서 오차 변화
